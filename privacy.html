Privacy policy

Effective date: October 1, 2026

This policy describes the personal Alraed Database Backup workflow operated by Mohammed Enad. The workflow runs on the owner's Windows computer and uses rclone to store database backups in the owner's authorized Google Drive account.

Information accessed and used

  • Database backup files: full SQL backup files produced from the owner's AlraedDb database. These files contain the information stored in that database and may include personal or business information.
  • Google Drive information: the backup files and folders available to the app, including names, identifiers, sizes, checksums and other metadata needed to upload, verify, list and manage backups.
  • Authorization tokens: OAuth tokens issued by Google after the owner grants consent, allowing the local tool to run scheduled uploads.
  • Local logs: operational details such as backup filenames, timestamps, completion status and errors, stored on the owner's computer.

The workflow requests the Google Drive drive.file scope. Its configured purpose is to manage its own backup folder and files. It does not request access to Gmail messages or unrelated Google Drive files.

Purpose and processing

Data is used to create a full database backup, upload it to Google Drive, check that the upload matches the local backup, and remove older backups under the retention setting. The backup scripts and rclone run locally; this informational website does not receive database files or OAuth tokens.

Storage and security

Backup files and logs are stored on the owner's Windows computer. Uploaded backups are stored in the owner's Google Drive. OAuth tokens are stored in the local rclone configuration file; access to that file must be restricted to trusted Windows users. Google Drive API transfers use HTTPS.

The supplied backup workflow does not separately encrypt the SQL backup files before upload. File access therefore depends on local folder permissions and the owner's Google Drive sharing settings. The owner is responsible for keeping credentials private and controlling access to backups.

Sharing and third parties

Google processes uploaded backups to provide Google Drive storage under its own terms and privacy policy. The workflow does not sell Google user data, use it for advertising, or transmit backups to additional services. A person with access granted by the owner to the local backup folder or Google Drive backup folder may be able to read its files.

GitHub Pages hosts these public informational pages and may process connection information to deliver the website under GitHub's privacy practices. These pages contain no embedded analytics, advertising, forms, or tracking scripts.

Retention and deletion

After a successful backup and verified upload, the supplied scripts retain the latest three managed completed backups in each location and permanently delete older managed backups. If backup or upload verification fails, existing backups are preserved, so more than three files may temporarily remain. Failed partial backups and local logs remain available for troubleshooting until the owner removes them.

The owner can delete local files and logs from Windows and uploaded backups from Google Drive. Revoking Google authorization stops future access; it does not automatically delete files already stored on the computer or in Google Drive.

Control over authorization

The owner can disable the Windows scheduled task at any time and revoke the app's access through the Google Account third-party connections settings. The owner can also remove the local rclone configuration to remove locally stored authorization tokens.

Changes and contact

This policy should be updated whenever the workflow's permissions, processing, retention or sharing practices change.
